## 2. Gap-анализ прототипа

Что в прототипе уже сделано как **визуальный и смысловой эталон**, и что нужно для реальной работы.

| Экран прототипа | Состояние | Что нужно построить | Фаза |
|-----------------|-----------|---------------------|------|
| **Дашборд** (KPI, поток, тональность, динамика секторов, топ источников, гео, персоны, здоровье парсеров) | Всё на `Math.random()` и константах | Агрегаты, реальные метрики, WebSocket-поток, настраиваемые виджеты, реальные данные здоровья из очередей | 0 (демо) → 4 |
| **Лента** (поиск, фасеты, период, сортировка, карточки, модал) | Фильтрация по массиву в браузере | Серверный поиск и фасеты, курсорная пагинация, фильтры в URL, сохранённые фильтры, полноценная страница материала | 2 |

| **Источники** (таблица, табы, конфиг парсера, добавление, AI-дискавери) | Моки, кнопки показывают тосты | Реестр, коннекторы, студия парсеров, запуск, логи, здоровье, дискавери | 1, 6 |
| **Алерты** | Карточки правил без логики | Движок правил, каналы доставки, история срабатываний, подавление дублей | 5 |
| **Конструктор отчётов** | Шаблоны и список-заглушка | Блочный конструктор, PDF/XLSX/PPTX, расписание, шаринг | 5 |
| **Пользователи и роли** | Роль переключается **в браузере** | Серверный RBAC, приглашения, 2FA, кастомные роли, ограничение по темам/территориям | 0, 7 |
| **Настройки** (интеграции, NLP-конвейер, тенант, локализация) | Переключатели без эффекта | Реестр настроек с реальным влиянием, интеграции, профиль региона | 0, 7 |
| **Тарифы и оплата** | Статичные карточки | Entitlements, учёт расхода, ЮKassa, чеки, автоплатежи | 8 |
| **Отсутствует вовсе** | — | Вход/регистрация/онбординг · публичный портал · страница материала/сюжета/сущности/территории · карта района · админка платформы целиком · журнал аудита · API-ключи · модерация · мобильная версия · состояния «пусто/ошибка/загрузка» | 0–9 |

**Мелкие дефекты прототипа** (исправляем при переносе, на смысл не влияют): у кнопок фасетов дублируется атрибут `class` (второй игнорируется — чипы теряют стили); опечатки («промпark», «Мульти-юродикция»); Tailwind/шрифты/Chart.js подгружаются с CDN (для продакшена всё собирается локально); интерфейс не адаптивен на мобильных (фиксированный сайдбар); нет ARIA-ролей у переключателей и модальных окон; значения подставляются в inline-обработчики (`onclick="window.open('${url}')"`) — на реальных данных это XSS-риск, в реальной сборке такое запрещено.

## 4. Лента и фильтры

**Фасеты** (из прототипа + расширение): сектор/тема (иерархия) · тип источника · источник/группа источников · тональность (5 градаций) · география (регион → город/район → населённый пункт; выбор на карте) · персоны · организации · сюжет · язык · «только оригиналы / включая перепечатки» · «только с изображениями» · надёжность источника (диапазон) · период (быстрые пресеты + произвольный).

**Поиск:** по заголовку, тексту, сущностям; морфология русского («урожай» найдёт «урожая»); фразы в кавычках, исключения (`-слово`), `OR`; подсказки; подсветка совпадений.

**Сортировка:** новые · старые · по тональности · по значимости (композитный скор: охват источников, размер сюжета, надёжность) · по источнику.

**Сохранённые фильтры:** личные и командные, с подпиской на «новые совпадения» (реалтайм, алерт или дайджест). Каждый фильтр = **URL** (можно отправить коллегам).

**DSL фильтра** — единый для UI, API и алертов: `{ q, from, to, sectors[], sources[], sourceTypes[], sentiment[], geo[], entities[], storyId, originalOnly, trust:{min,max} }`.

**Подача:** карточки · компактный список · таймлайн · режим «чтение» (быстрый просмотр без ухода со страницы). Бесконечная прокрутка с виртуализацией.

## 5. Аналитика

### 5.1 Каталог метрик

| Группа | Метрики |
|--------|---------|
| Объём | Число материалов, динамика по часам/дням, доля оригиналов, доля перепечаток |
| Тональность | Индекс −1…+1 (скользящее окно), распределение 5 градаций, доля негатива, тональность по сущностям |
| Источники | Объём, скорость публикации («кто первый»), оригинальность, цитируемость, надёжность, сравнение |
| Темы | Динамика, тепловая карта «тема × источник», новые/растущие темы, облако тем |
| Сущности | Число упоминаний, **Share of Voice**, тональность вокруг сущности, совместные упоминания, граф связей |
| Территории | Интенсивность инфоповодов по районам (карта-хороплет), «белые пятна» (территории без освещения) |
| Сюжеты | Размер, длительность, динамика, участники, охват источниками |
| Активность | Часы суток/дни недели (часовой пояс тенанта) |
| Аномалии | Всплески объёма/негатива, «вбросы» (быстрый рост в слабых источниках без подтверждения СМИ) |
| Показатели | Ряды Росстата/ЕМИСС/ЦБ рядом с динамикой публикаций |

### 5.2 Дашборды

Сетка виджетов (перетаскивание/размер), готовые шаблоны («Пульс региона», «Репутация организации», «Агросектор», «Сравнение СМИ»), личные и командные дашборды, общий период/фильтр поверх всех виджетов, ссылка на дашборд (приватная, с сроком), режим «на экран» (киоск) для телевизора в кабинете руководителя.

### 5.3 Семантический слой

Клиент запрашивает `POST /v1/analytics/query` с белыми списками измерений/метрик/фильтров — получает данные для графика. Никакого произвольного SQL от клиента; результат кэшируется; доступ режется по роли и ограничениям тенанта (темы/территории).

## 6. Отчёты и «статьи на лету»

### 6.1 Конструктор отчётов

Шаблон = последовательность **блоков**: заголовок/текст, KPI-плитки, график (любой из аналитики), таблица, топ-материалы, цитаты, карта, **AI-нарратив** (абзац-пояснение к данным), оглавление, титул. Выходные форматы: **онлайн-страница** (живая, с обновлением), **PDF**, **XLSX**, **PPTX**, CSV. Шаблоны из прототипа: «Медиаметрия региона», «Анализ тональности», «Карта упоминаний персон», «Сравнение источников», «Отраслевой дайджест», «Автообзор (AI)».

**Фирменный стиль тенанта:** логотип, цвета, шрифты, колонтитулы, юридическая сноска.

**Расписание и доставка:** ежедневно/еженедельно/ежемесячно/по событию → email, Telegram, ссылка в кабинете; версии отчётов; публичный/приватный шаринг со сроком жизни.

### 6.2 Автообзоры и сводки (AI, строго с источниками)

Принцип: **числа и факты берёт код, LLM пишет связный текст**.
1. Выборка материалов/метрик по заданию (период, отрасль, территория).
2. Код считает цифры (динамика, доли, топ-N), собирает «пакет фактов» со ссылками на материалы.
3. LLM получает пакет и пишет обзор в заданном стиле/объёме, **с обязательными ссылками** `[1]`, `[2]` на материалы; формат вывода — по схеме.
4. Проверка: каждое число сверяется с пакетом фактов; утверждения без ссылок помечаются/удаляются.
5. Для публичного портала — шаг ручной проверки редактором (настройка `reports.auto.requireReview`); пометка «подготовлено с помощью ИИ».

Результат оформляется как красивая статья: заголовок, лид, врезки с графиками, цитаты, список источников.

## 7. Алерты и уведомления

| Тип правила | Пример |
|-------------|--------|
| **Ключевые слова/фразы** | «дизтопливо», «дефицит», «авария» + область (источники, территории) |
| **Сущность** | любое упоминание «губернатор», «АО Алтай-Нефть» |
| **Тема + тональность** | негатив по теме «ЖКХ» в Барнауле |
| **Порог** | > N материалов за час по теме |
| **Аномалия** | всплеск относительно нормы (z-score) |
| **Появление нового сюжета** | новый кластер из ≥ 3 источников |
| **Состояние системы** (для админов) | парсер упал, очередь растёт, бюджет AI на исходе |

**Свойства:** уровень (критический/важный/информационный), каналы (Telegram, email, web-push; SMS — по запросу), расписание «не беспокоить», **подавление дублей** (группировка: «+12 материалов по теме за последний час» вместо 12 сообщений), эскалация (если не подтверждено — повторить/передать), история срабатываний, «пробный прогон» правила на прошлых данных («сработало бы 18 раз за неделю») до включения.

**Telegram-бот:** `/search`, `/subscribe`, `/digest`, быстрые карточки материала, кнопки «открыть», «тишина на 2 часа», «отписаться».

## 8. Роли и права

### 8.1 Модель

Доступ = **роль (набор разрешений) × ограничения области × тариф (entitlements)**.

- **Разрешения** — атомарные: `feed:read`, `analytics:build`, `export:run`, `report:create`, `report:schedule`, `alert:manage_team`, `source:propose`, `source:manage`, `parser:edit`, `article:moderate`, `taxonomy:edit`, `entity:merge`, `user:manage`, `role:manage`, `tenant:settings`, `billing:manage`, `apikey:manage`, `audit:read`, … Платформенные: `platform:tenants`, `platform:ai`, `platform:settings`, `platform:flags` и т.д.
- **Роли** — наборы разрешений. Системные роли неизменны; **кастомные роли** (Enterprise, Фаза 7) — тенант собирает из разрешений.
- **Ограничения области (ABAC)**: доступ только к выбранным **темам**, **территориям**, **группам источников** (клиент «агро» видит только агро).
- **Entitlements тарифа** включают/выключают функции и лимиты независимо от роли.
- Проверяется **на сервере** одним модулем политик + RLS в БД. Интерфейс лишь скрывает недоступное.

| Алерты | — | Email | Все каналы | Все каналы + SLA |
| Отчёты/экспорт | — | — | PDF / Excel | + PPTX, брендинг |
| API | — | — | Да | Расширенный |
| Особое | — | — | — | Приватный контур, SSO, кастомные роли, менеджер |

### 9.2 Entitlements (что реально ограничиваем)

`sources.active` · `articles.delivered_per_month` (материалы, попавшие в ленту тенанта; сбор общий, считаем доставку) · `seats` · `ai.tokens_per_month` · `history.depth_days` (**глубина доступного архива** — удобный дифференциатор) · `reports.per_month` · `exports.per_month` · `alerts.rules` · `api.requests_per_month` · флаги функций (`feature.pptx`, `feature.api`, `feature.custom_roles`, `feature.private_sources`, …). Все значения — данные тарифа в БД и **редактируются в админке** (без правки кода).

### 9.3 Жизненный цикл подписки

`trial → active → past_due → grace (льготный период) → suspended → canceled`. При `suspended` данные не удаляются, доступ ограничивается до «только чтение/экспорт своих данных». Апгрейд — немедленно с пропорциональным пересчётом; даунгрейд — со следующего периода; предупреждения о приближении к лимитам (80/100%); докупаемые пакеты (AI-токены, доп. источники).

### 9.4 Платежи

- **Абстракция `PaymentProvider`:** создание платежа, статус, сохранение способа оплаты, автоплатёж, возврат, вебхуки. Реализации: **Test (фиктивный, для разработки)**, **ЮKassa**; далее — по необходимости (СБП-провайдеры, зарубежные для других рынков).
- **ЮKassa:** создание платежа с `Idempotence-Key`; сохранение способа оплаты для автопродления; вебхуки (успех, отмена, возврат) — каждое событие **перепроверяется запросом статуса платежа** и обрабатывается идемпотентно; **чеки 54-ФЗ** (товар/услуга, ставка НДС, СНО — поля настраиваются после определения юрлица); возвраты; СБП.
- **Устойчивость:** повторные и перепутанные по порядку вебхуки не ломают состояние; сверка платежей по расписанию («реконсиляция»); журнал всех событий платёжных систем.
- **Дожим (dunning):** повторные попытки списания (например, через 1/3/7 дней) + письма; затем `grace` → `suspended`.
- **Юрлица:** оплата по счёту (банковский перевод) с ручным/полуавтоматическим подтверждением, акты в PDF; электронный документооборот — позже. Возможности ЮKassa для безналичных счетов уточняются на этапе Фазы 8.
- **Налоги и документы:** формируются из данных тарифа/платежа; финальные настройки — после определения юрлица.
- **Админка биллинга:** редактор тарифов и entitlements, ручное начисление/продление, промокоды, платежи и возвраты, сверка, метрики (MRR, churn).

## 10. Админка платформы и реестр настроек

### 10.1 Принцип «максимального контроля»

Любое поведение, которое можно захотеть изменить без выпуска новой версии, — **настройка в реестре**:
- типизированная (тип, диапазон, допустимые значения — схема Zod);
- с **областью действия** и наследованием: `платформа → тенант → источник → пользователь` (более узкая область перекрывает широкую; для каждого ключа задано, на каких уровнях его можно менять);
- с **историей изменений** (кто/когда/что/зачем), **откатом** и записью в аудит;
- с признаком «секрет» (шифруется, не показывается), «требует перезапуска», «влияет на биллинг»;
- с правами: кто может менять (разрешение);
- с **описанием и подсказками** в интерфейсе и валидацией «до применения» (что изменится).

## 11. Каталог источников и AI-дискавери

Владелец сформулировал два пути: **(1) ручное добавление с инструкциями парсинга** и **(2) автоматический поиск на основе ИИ**. Оба сходятся в одном **каталоге источников**.

### 11.1 Путь 1 — ручное добавление

Форма: URL → автоопределение типа (RSS? sitemap? нужен ли JS-рендеринг?) → автопредложение селекторов → **пробный прогон с превью** (3–5 страниц, что извлеклось) → правка конфига → расписание/территория/тема/политика контента → сохранение → первичный прогон → ретро-сбор.

### 11.2 Путь 2 — AI-дискавери (Фаза 6)

> LLM не ходит в интернет сам. Поиск и обход выполняет код; LLM генерирует запросы и классифицирует найденное.

1. **Задание.** Регион, уровни территорий (`core` → `cities` → `districts` → `settlements`), отрасли (госсектор, агро, пищепром, ТЭК, статистика, …), типы ресурсов, лимиты. Пример: «Алтайский край: сперва открытые государственные источники, затем статистика и отраслевые ресурсы; ядро — Барнаул, потом города края; сёла и посёлки — опционально».
2. **Генерация кандидатов:**
   - запросы к поисковому провайдеру (интерфейс `SearchEngine`: SearXNG на своём сервере по умолчанию, Яндекс Search API и др. — по ключу), запросы строятся по шаблонам и территориям («новости <город>», «районная газета <район>», «администрация <район> официальный сайт»…);
   - каталоги и открытые данные (например, реестр зарегистрированных СМИ Роскомнадзора, перечни сайтов органов власти — доступность и формат проверяются при реализации), каталоги Telegram/VK-сообществ по территории — с учётом условий использования;
   - расширение по графу ссылок известных источников (ссылки «партнёры», «СМИ района», перепечатки).
3. **Нормализация и дедупликация** по домену/аккаунту.
4. **Автопроверки:** ресурс жив (HTTP, TLS), дата последней публикации, наличие RSS/sitemap, **«парсится ли»** (на 5 страницах извлекаются заголовок/дата/текст — доля успеха), темп публикаций, язык.
5. **Классификация** (эвристики + LLM): тип, отрасль, территория, аудитория, регистрационный статус.
6. **Рейтинг авторитетности (0–100):** возраст и регулярность, объём, оригинальность (доля неперепечатанного), цитируемость другими источниками каталога, полнота метаданных, технические показатели; гос. источники получают повышающий коэффициент (формула — настройка).
7. **Сегментация и каталогизация:** теги «отрасль × территория × тип», связи «источник → перепечатывает → источник».
8. **Очередь кандидатов** (админка → «Модерация»): карточка с доказательствами (скриншот, превью извлечения, оценки, возможные дубли, риск-пометки: чат/форум/спорный источник) → **утвердить / отклонить / отложить**.
9. **Автогенерация конфига** → пробный прогон → **ретро-сбор** (по настройкам) → пост-проверка качества через N дней и пересмотр рейтинга.

**Территориальное расширение:** уровни включаются настройкой; для новых территорий дискавери запускается повторно и обнаруживает только то, чего ещё нет.

### 11.3 Верификация стартового реестра (Фаза 1)

Список из прототипа (18 записей) — **плейсхолдер**: домен и название могут не принадлежать одному изданию, часть адресов может не существовать (не проверялось). Процедура:
1. Для каждой записи — автопроверка (§11.2 п. 4) и сверка идентичности (название на странице «о нас», регистрация СМИ).
2. Для неподтверждённых — поиск правильного адреса.
3. Расширение до 20–30 источников по приоритетам: открытые гос. порталы (края, Барнаула, министерства, статистика) → крупные региональные СМИ → отраслевые → городские издания (Бийск, Рубцовск, Новоалтайск и др.) → Telegram/VK.
4. Итог — таблица со статусами (подтверждён / заменён / исключён) и утверждение владельцем.

## 12. UX и дизайн-система

**Цель владельца:** современно, понятно, серьёзно, удобно; красиво оформленные на лету статьи, обзоры и сводки — не только графики.

**Развиваем:**
| Что | Как |
|-----|-----|
| **Токены** | Цвета/радиусы/отступы — CSS-переменные; бренд тенанта подменяется токенами (white-label) |
| **Темы** | Светлая и тёмная, переключатель, учёт системной |

| **Командная палитра ⌘K** | Реальный поиск по материалам/сущностям/источникам + команды («создать алерт», «перейти к…») |
| **Редакционный слой** | Типографика для статей и обзоров (читаемая колонка, врезки, цитаты, подписи к графикам, печатная версия), шаблоны «Сводка дня», «Обзор недели», «Отраслевой разбор» |
| **Данные** | Единые форматы чисел/дат/процентов (ru-RU), сокращения (тыс., млн), понятные подсказки на графиках, возможность скачать любую диаграмму (PNG/SVG/CSV) |
| **Производительность** | Виртуализация списков, ленивая подгрузка графиков, оптимистичные обновления, кэш |
| **Тексты** | Простой язык: «негатив», а не «NG»; объяснения метрик в подсказках («Индекс тональности: как считается») |
